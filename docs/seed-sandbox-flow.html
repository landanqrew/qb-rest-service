scripts/seed_sandbox.py — process flow

A create-only, one-off tool that seeds a QBO sandbox from exported production Customers and Items. It intentionally never reads production tokens or creates Chart-of-Accounts records.

Safety outcomes

  • abort Existing seed state or Customer/Item counts above the threshold prevents a normal write run.
  • force --force bypasses the preflight but does not clear stale state; it is an intentional operator override.
  • skip Unsupported item type, unresolved sandbox account, QBO validation error, or missing response ID leaves the individual record uncreated and records why.
  • fail A source parent-reference cycle raises an error instead of making an invalid, unordered write attempt.
Customer transformation details

For each active Customer, the script removes source-owned fields (Id, SyncToken, metadata, sparse flags) and drops realm-specific CustomerTypeRef, PaymentMethodRef, and SalesTermRef. A sub-customer/Job is written only after its parent; its ParentRef.value is replaced with the sandbox ID. If that parent was not created, the script deliberately drops ParentRef and Job rather than posting a dangling production ID.

Item transformation details

The script supports Service, Inventory, and NonInventory. Before creating an Item it reads the sandbox Account list and maps each source IncomeAccountRef, ExpenseAccountRef, and AssetAccountRef by the source reference’s account name. If a required account name is missing in the sandbox, the item is skipped—never written with a production account ID. Sub-item parents are mapped from the saved Item state in the same way as Customer Jobs.

QBO call and failure handling

Writes are paced by SANDBOX_WRITE_DELAY_SEC and pass through _post_with_retry(). Rate-limit and transient server responses are retried with exponential backoff. A deterministic APIError records its HTTP status, Fault.Error[] code/message, and intuit_tid in the summary before the script moves to the next record. A successful QBO response must contain the created entity ID before the state map is updated.
